# 个股 A/B/C 多周期图表方案

状态：用户已批准；已实施并部署，完成验收。

## 范围与行为

覆盖所有使用共享 StockChart 的个股图表，包括 Watchlist、个股详情与股票抽屉。支持日、周、月、30 分钟、120 分钟；指数和板块不在范围内。保留当前指标开关默认值，A/B/C 仍由用户手动开启。

日线继续读取现有正式 A/B 结果，保持 C 日线行为。其他周期按对应 OHLCV 重新计算并显示观察、买点和失效/模拟退出标记。回放结果明确显示周期、规则来源、日线背景日期及缺数据原因。

A/B 的均线、ATR、MACD、量能、回调和确认按所选周期计算；市场、行业、RPS、生命周期资格仍来自当时已知的完整日线。分钟柱统一使用前一完整交易日背景；周/月柱使用截止该柱完成时已可用的背景。禁止用最新日线背景覆盖历史，也不制造分钟 RPS。缺少必需背景时阻断对应路径。

C 使用对应周期的 OHLC 独立计算，保留右侧确认，信号落在确认柱而非回填到极点。非日线的窗口和冷却单位是 K 线根数，数值先沿用现有配置并明确标示，不按单只股票调参。模拟退出维持实验性质。

新周期结果仅用于图表回放，不写正式 Watch 状态、事件、扫描记录或交易，不增加邮件及后台任务。规则只读加载，注明版本；同股多分组时保留规则来源，避免静默混用。

## 实施拆分与文件

每阶段分小任务推进，每个实现批次控制在三份业务文件以内，测试随批次补充。

1. 纯计算：新增 `backend/quant_engine/watch/chart_replay.py`，必要时在 `watch/engine.py` 提取或复用纯判断；修改 `research/structure_turning.py`，支持完整时间戳、周期和按根计数。使用独立手工夹具验证因果性。
2. 只读接口：新增 `backend/app/api/v1/chart_signals.py` 并在 API 路由注册。复用 `stock.py` 图表取数/聚合函数和 `minute_chart.py` 有界缓存，确保信号与图表相同来源和截止时点。接口按股票、周期、截止日和显示范围请求，返回 A/B/C 及数据状态；不接受未经校验的外部行情作为正式输入。避免为每根柱查询数据库。
3. 前端接入：更新 `frontend/src/lib/api.ts`、共享 `StockChart.tsx`，以及标记辅助文件 `stockChartWatchMarkers.ts`、`structureCandidatePresentation.ts`、`StructureStrategyPanel.tsx` 中确实需要修改的部分。取消日线专属限制前先接入真实周期计算。查询键包含周期和范围，分钟标记保留完整时间戳；切换股票/周期时不显示旧信号。所有共享个股宿主统一生效。
4. 验收与交付：新增后端和前端针对性测试；独立目录生产预构建，通过后切换当前项目服务，有失败回滚；实点 Watchlist 和详情/抽屉的五种周期。

## 风险及验证

- 未来数据泄漏：修改未来行情或未来背景，不得改变此前已确认信号。
- 未完成柱：分钟发布缓冲、周/月完成边界必须明确，形成中柱不产生确认信号。
- 时间戳截断：同日多个 30/120 分钟信号分别定位，不能被日期截断合并。
- 单位混用：观察窗口、setup 年龄和冷却均按该周期根数验证；日线回归保持。
- 数据不足/异常：空行情、缺日线背景、非法周期、暖机不足、非支持市场分别有可见状态；不降级资格门。
- 正式链路污染：只读数据库连接，接口前后正式表零新增/修改；无 schema 初始化或默认配置写入。
- 图表串用：快速切换周期/股票，标记及面板与当前行情一致，开关保持用户设置。

每个新功能至少覆盖正常、边界、错误三类用例。以通用夹具与不同股票验证，不围绕一只股票拟合。检验标记对应真实可见画布，并核对与接口返回时间戳的一致性。

## 资源预算

仅打开图表且开启路径时按需计算；非日线每请求最多 520 根完成柱，日线保留现有兼容范围。日线背景一次批量只读加载，禁止每柱 SELECT。复用分钟缓存现有 32 键/8MB、两路并发限制，不增加定时唤醒、批量全 Watchlist 回放或持久缓存。

目标：新增纯计算 p95 不高于 100ms、额外内存不高于 5MB；交付时实测并报告，超出则先优化有界算法。记录接口延迟、请求量、进程 RSS/CPU/线程、数据库句柄、生产构建峰值和新增磁盘体积；无后台日志持续增长。
